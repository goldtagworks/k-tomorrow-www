# Trust Review — 공공기관 신뢰성 검증

## 워크플로우

1. **공공기관 신뢰 3종 세트 검증** — P0 필수 항목
   - [ ] 상위 기관 로고 체인이 푸터 또는 Trust 섹션에 존재하는가
   - [ ] 웹접근성 인증 마크(또는 WCAG 준수 표시)가 존재하는가
   - [ ] 전화번호 또는 이메일이 헤더/히어로/푸터에 직접 노출되는가
   - 하나라도 누락 시: **P0 이슈** 즉시 발행

2. **공공기관 톤앤매너 검증**
   - [ ] 과장 표현 사용 여부 ("혁신적인", "획기적인", "차세대" 등 금지 표현)
   - [ ] 구체적 수치 기반 설명인가 (추상적 마케팅 카피 vs 실제 기능 명시)
   - [ ] 공공기관이 기대하는 격식 수준인가 (너무 캐주얼하지도, 너무 딱딱하지도 않은)
   - [ ] 포용적 어조인가 (시니어, 외국인을 환영하는 표현)

3. **B2G 전환 동선 검증**
   - [ ] "도입 문의" CTA가 명확히 존재하는가
   - [ ] 기관 의사결정자가 30초 안에 핵심 가치를 파악할 수 있는가
   - [ ] 제안서 다운로드 또는 데모 체험 경로가 있는가
   - [ ] 실적 데이터(도입 기관 수, 수강 완료율 등)가 신뢰할 수 있게 표시되는가

4. **다문화 포용성 검증**
   - [ ] 14개 언어 지원이 시각적으로 강조되는가 (히어로 수준)
   - [ ] 언어 선택 UI가 접근하기 쉬운 위치에 있는가
   - [ ] 다문화 대상 이미지/아이콘이 포용적인가 (특정 인종/문화 편향 없음)

5. **신뢰 요소 품질 검증**
   - [ ] 추천사가 실제 느낌인가 (현실적 이름, 직함, 기관명)
   - [ ] 통계 수치가 유기적인가 (라운드 넘버 "50,000+" 금지 → "47,200+" 사용)
   - [ ] 인증 마크/로고가 깨지지 않고 적절한 크기로 표시되는가

6. **감사 리포트 작성** — 이슈 목록 + 수정 지시서

## 도구 사용법

- `Read`: index.html 읽어서 전체 분석
- `WebSearch`: 공공기관 웹사이트 가이드라인 참조 (필요시)
- `Write`: 감사 리포트를 docs/ 디렉토리에 저장

## 출력 규칙

- 산출물: `docs/trust-review-report.md`
- 이슈 형식:
  ```
  ## [P0] 상위 기관 로고 누락
  - 위치: Footer 섹션
  - 현재 상태: 기관 로고 없음
  - 수정 지시: 푸터에 상위 기관(예: 교육부, 해당 지자체) 로고 + k-tomorrow 로고 체인 추가
  - CSS: `.footer-logos { display: flex; gap: 24px; align-items: center; }`
  ```
- 심각도 분류: P0 (필수 수정) / P1 (강력 권고) / P2 (권고) / P3 (개선 제안)
- 신뢰성 점수: 0~100 (70 미만: 수정 필수, 70~85: 수정 권고, 85+: 승인)

## 에러 처리

- HTML 파일이 아직 없는 경우: 디자인 문서(docs/) 기반으로 사전 검증
- 기관 로고 에셋이 없는 경우: 플레이스홀더 위치만 확인하고 에셋 제공 요청
