# Frontend Rules — 프론트엔드 디자인 하드룰

이 스킬은 design-system-architect와 frontend-builder가 공유하는 디자인 규칙 레퍼런스입니다.
HTML/CSS 구현 시 반드시 준수해야 하는 룰을 정의합니다.

## 하드룰 목록

### 1. 구성 (Composition)
- **한 구성 원칙**: 첫 뷰포트는 하나의 구성으로 읽혀야 한다. 대시보드가 아닌 이상 여러 패널/위젯 금지.
- **브랜드 퍼스트**: 브랜드(K-Tomorrow)가 히어로급 시그널이어야 한다. nav 텍스트나 eyebrow 수준이면 부족.
- **브랜드 테스트**: nav를 제거했을 때 다른 브랜드 사이트로 보인다면 브랜딩이 약한 것.

### 2. 히어로 (Hero)
- **풀블리드만**: 랜딩 페이지의 히어로 이미지는 edge-to-edge 배경이 기본. 인셋, 사이드패널, 라운드 카드, 콜라주, 플로팅 이미지 금지.
- **히어로 예산**: 첫 뷰포트에는 다음만 허용:
  - 브랜드 표시
  - 헤드라인 1개
  - 서포팅 문장 1개
  - CTA 그룹 1개
  - 주요 이미지 1개
- **히어로에 금지**: 통계, 일정, 이벤트 목록, 주소, 프로모, "이번 주" 콜아웃, 메타데이터, 보조 마케팅 콘텐츠
- **오버레이 금지**: 히어로 미디어 위에 분리된 라벨, 플로팅 뱃지, 프로모 스티커, 칩, 콜아웃 박스 금지

### 3. 카드 (Cards)
- **기본: 카드 없음**. 히어로에는 절대 카드 금지.
- **허용 조건**: 사용자 인터랙션의 컨테이너일 때만 카드 허용.
- **테스트**: border, shadow, background, radius를 제거해도 인터랙션이나 이해에 지장이 없다면 카드가 아니어야 한다.

### 4. 섹션 (Sections)
- **역할 1개**: 각 섹션은 하나의 목적, 하나의 헤드라인, 보통 하나의 서포팅 문장.
- **클러터 제거**: pill 클러스터, stat strip, 아이콘 행, 박스 프로모, 일정 스니펫, 경쟁하는 텍스트 블록 금지.

### 5. 비주얼 (Visual)
- **실제 비주얼 앵커**: 이미지는 제품, 장소, 분위기, 맥락을 보여줘야 한다. 장식용 그라데이션이나 추상 배경은 메인 비주얼이 아님.
- **배경**: 플랫 단색 배경 금지. 그라데이션, 이미지, 미묘한 패턴으로 분위기 구축.

### 6. 모션 (Motion)
- **존재감과 계층**: 모션은 존재감과 시각 계층을 만드는 데 사용. 노이즈가 아님.
- **최소 2~3개**: 의도적인 모션을 최소 2~3개 포함 (scroll reveal, hover, entrance 등).

### 7. 타이포그래피 (Typography)
- **표현적 서체**: 기본 스택 (Inter, Roboto, Arial, system) 사용 금지.
- **의도적 선택**: 한글 최적화, 브랜드 톤에 맞는 서체.

### 8. 컬러 (Color)
- **명확한 비주얼 방향**: CSS 변수로 정의.
- **보라색 편향 금지**, **다크 모드 편향 금지**.

### 9. 반응형 (Responsive)
- **데스크톱 + 모바일 필수**: 두 환경 모두 정상 로딩 보장.
- **모바일 퍼스트 CSS** 권장.

### 10. 기술 (Technical) — 정적 HTML 특화
- React, 프레임워크, 빌드 도구 사용하지 않음
- 순수 HTML5, CSS3, 바닐라 JavaScript만 사용
- 외부 CDN은 폰트 로딩 정도만 허용
- JS는 프로그레시브 인핸스먼트 — JS 없이도 콘텐츠 접근 가능
- 시맨틱 HTML5 요소 사용 (section, article, nav, header, footer, main)

## 적용 시점
- **design-system-architect**: 토큰 설계 시 룰 7, 8에 맞는 값 선택
- **frontend-builder**: HTML/CSS 구현 시 전체 룰 준수
- **trust-reviewer**: 검증 시 룰 준수 여부 체크

## 예외
기존 웹사이트나 디자인 시스템 내에서 작업할 경우, 기존 패턴·구조·비주얼 언어를 유지한다.
