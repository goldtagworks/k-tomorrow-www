# Trust Audit — 신뢰성·접근성 감사

## 워크플로우

### 1. 파일 읽기
검증 대상 파일을 전부 읽는다:
- `index.html` — HTML 구조, 콘텐츠, 메타 정보
- `site.css` — 스타일, 토큰 사용, 반응형
- `logo.svg`, `og-image.svg` — 브랜드 에셋

### 2. 신뢰성 감사 (Trust Audit)

**T1. 브랜드 존재감**
- 첫 뷰포트에서 "K-Tomorrow"가 즉시 인식되는가
- 로고 크기와 위치가 히어로급인가 (nav 구석이 아닌)
- 브랜드 테스트: nav 제거 시 다른 사이트로 보이는가

**T2. 전문적 톤**
- 공공기관 담당자가 "이 플랫폼을 도입해도 되겠다"고 느낄 수 있는가
- 과도한 마케팅 어투 없이 전문적인가
- 기능 설명이 구체적이고 명확한가

**T3. 연락처 접근성**
- 이메일, 전화번호 등이 스크롤 없이 또는 1 클릭으로 접근 가능한가
- footer에 명확한 연락처 정보가 있는가

**T4. 실적·증빙**
- 기관 수, 사용자 수, 지원 언어 수 등 구체적 수치가 있는가
- 파트너/고객 로고가 있는가 (없으면 대체 신뢰 요소)

**T5. 법적 페이지**
- 개인정보처리방침 링크가 footer에 존재하는가
- 이용약관 링크가 footer에 존재하는가

### 3. 접근성 감사 (Accessibility Audit)

**A1. 텍스트 크기**
- CSS에서 본문 font-size 확인: ≥ 18px (1.125rem)
- 버튼 텍스트: ≥ 16px
- 모바일에서 축소되지 않는지 확인

**A2. 터치 영역**
- 버튼, 링크의 min-height/min-width: ≥ 48px
- padding으로 터치 영역 확보 확인

**A3. 명암비**
- 주요 텍스트 색상 vs 배경색 조합 추출
- WCAG AA 기준 확인:
  - 일반 텍스트: 4.5:1 이상
  - 대형 텍스트 (24px+ 또는 bold 19px+): 3:1 이상
- 문제 조합 목록화

**A4. 키보드 내비게이션**
- 모든 인터랙티브 요소에 tabindex 또는 네이티브 포커스
- :focus 스타일 존재 여부
- focus-visible outline 확인

**A5. Skip Link**
- `<a class="skip-link" href="#main">` 존재 확인
- 시각적으로 숨기되 포커스 시 표시되는지 확인

**A6. ARIA & 시맨틱**
- 의미 있는 이미지에 alt 텍스트 존재
- 장식용 이미지에 aria-hidden="true" 또는 빈 alt
- 랜드마크(header, main, footer, nav) 사용 확인
- 모바일 메뉴에 aria-expanded, aria-controls

**A7. 반응형**
- 360px(모바일)에서 가로 스크롤 없는지
- 1440px(데스크톱)에서 레이아웃 정상인지
- 중간 브레이크포인트에서 깨지는 부분 없는지

### 4. 프론트엔드 하드룰 감사

### 5. 이슈 리포트 작성

각 이슈를 등급으로 분류:

| 등급 | 기준 |
|------|------|
| **Critical** | 신뢰 훼손 또는 접근성 차단 — 즉시 수정 필요 |
| **Major** | 사용성 저해 또는 하드룰 위반 — 배포 전 수정 |
| **Minor** | 개선 사항 — 다음 이터레이션에 반영 |

리포트 형식:
```markdown
## Trust Audit Report — K-Tomorrow

### 점수 요약
| 영역 | 점수 (10점) | 등급 |
|------|------------|------|
| 신뢰성 | X | A/B/C |
| 접근성 | X | A/B/C |
| 하드룰 | X | A/B/C |
| 기술 | X | A/B/C |

### Critical Issues
### Major Issues
### Minor Issues
### 통과 항목
```

### 6. 재검증 (Recheck)
이전 이슈가 수정된 후 재검증 수행:
- 이전 이슈 목록 로드
- 수정된 부분만 집중 확인
- 새로운 이슈 발생 여부 확인
- 업데이트된 리포트 작성

## 도구 사용법
- **Read**: HTML/CSS 파일 전체 읽기
- **Grep**: 특정 패턴 검색 (aria-label, alt, font-size 등)
- **Write**: `docs/trust-review.md` 리포트 작성

## 출력 규칙
- 산출물: `docs/trust-review.md`
- 모든 이슈에 **위치(파일:라인)**, **현재 상태**, **기대 상태**, **수정 제안** 포함
- 점수는 10점 만점, 등급은 A(9-10) / B(7-8) / C(5-6) / D(~4)
- 수정 제안은 구체적 코드 레벨 (추상적 피드백 금지)

## 에러 처리
- 파일 없음: 해당 파일이 아직 생성되지 않았다고 보고, 생성 요청
- 명암비 계산 불확실: 근사값 제시 + 수동 확인 권장 표시
- 이미지 분석 불가: alt 텍스트 존재 여부만 확인, 내용 적절성은 사용자 확인 요청
