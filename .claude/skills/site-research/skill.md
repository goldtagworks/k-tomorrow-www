# Site Research — LMS/공공기관 벤치마킹 분석

## 워크플로우

1. **대상 선정** — 분석할 LMS/공공기관/교육 사이트 목록 확정
   - 한국: 디지털 배움터, 다누리, NILE, K-MOOC, 들배움
   - 해외: Coursera, edX, Khan Academy (접근성 측면)
   - 사용자가 추가 사이트를 지정한 경우 포함

2. **패턴 추출** — 각 사이트에서 다음 항목을 조사
   - 히어로 섹션 구조 (슬로건, 검색, 퀵메뉴, 비주얼)
   - 네비게이션 패턴 (메뉴 깊이, 메가메뉴, 모바일 대응)
   - 색상 팔레트 (주색, 보조색, CTA 강조색)
   - 신뢰성 UI (인증마크, 기관 로고, 전화번호, 통계 수치)
   - 접근성 UI (글꼴 크기 조절, 다국어 전환, 고대비 모드)
   - 전환 동선 (B2C 수강신청 vs B2G 도입 문의)
   - 푸터 구조 (연락처, SNS, 관련 기관, 인증마크)

3. **통합 분석** — 사이트별이 아닌 패턴별로 통합 분석
   - 공통 디자인 패턴 TOP 5
   - 공공기관 특유의 신뢰성 UI 패턴
   - 노령자/외국인 접근성 패턴
   - LMS 전환 최적화 패턴
   - 차별화 기회 영역 (기존 사이트의 약점)

4. **적용 제안** — k-tomorrow에 적용할 구체적 디자인 방향 제시

## 도구 사용법

- `WebSearch`: 사이트별 최신 정보 검색, 디자인 트렌드 조사
- `WebFetch`: 실제 사이트 HTML 구조 분석
- `Read`: 기존 벤치마크 리포트(docs/benchmark-report.md) 참조
- `Write`: 분석 결과를 docs/ 디렉토리에 저장

## 출력 규칙

- 산출물: `docs/benchmark-report.md`
- 형식: 패턴별 통합 분석 (사이트별 나열 금지)
- 각 패턴에 "시사점" 포함 (k-tomorrow 적용 방향)
- 표/비교 매트릭스 활용하여 한눈에 비교 가능하게
- 200줄 이내

## 에러 처리

- 사이트 접속 불가 시: 해당 사이트 건너뛰고 접근 가능한 사이트로 대체
- 정보 부족 시: WebSearch로 스크린샷/리뷰/분석 기사 검색하여 보완
- 기존 벤치마크 리포트가 있는 경우: 업데이트가 필요한 부분만 보강
